# Generic client setup and service UI contracts

F supplies reusable pairing and protocol checks. Open Dot is the shared client built with F. Each compatible deployment owns its Dots, access policy, storage, and tools. No domain workflow is encoded here.

`near-function/setup` is browser-compatible pure client code: `defineBackend`, `checkConnection`, and `setupPresentation`. `near-function/setup/server` is a Node-only local reference pairing authority using cryptographic random codes and hashed code storage. `near-function/mcp-ui` supplies pure declarative service UI composition and action authorization. These paths are the proposed integration exports; the parent repository owns the actual manifests.

An installed client accepts a `near-dot://setup/pair?code=...` link through its own deep-link handler. A desktop client can show `setupPresentation(grant).qrPayload` as a QR code; a mobile client scans it or the user manually enters the identical link. QR is another representation of the same bearer capability, not separate authentication. No QR renderer or OS URL-handler registration is implemented here.

The authority issues links only after explicit owner consent, for one preselected authenticated audience, with a maximum five-minute lifetime and exact allowlisted callback. Provider credentials never belong in the link. Redemption requires that authenticated audience and its own consent; an unaccepted permission cannot be added. Successful redemption consumes the code once and records the pairing in authority-owned storage. Choosing a Dot only succeeds for that recorded audience pairing. Wrong audience or declined consent can retry before expiry. Owner cancellation is final; a client AbortSignal before redemption does not consume the grant. Callback routing accepts only exact configured HTTPS callbacks or `near-dot://setup/complete`, without query/fragment credentials or redirects.

Caller-supplied principal IDs mean the host has already authenticated those principals; these IDs are not an authentication mechanism. The local authority has atomic synchronous mutation within one process, at most 1,000 retained grants, and prunes expired tombstones after one additional maximum lifetime during issuance. It is ephemeral, loses pairings on process restart, and stops issuance at capacity. A production multi-process service needs authenticated transport, rate/body limits, durable transactionally single-use storage, pairing revocation, and host-owned session issuance. A returned pairing is configuration, not a bearer session credential. No real account, invite, email, network request, or session token is created.

Installing or pairing does not establish authentication, protocol compatibility, authorization, or reachability. `checkConnection` requires host-observed evidence of each. A desktop loopback backend is not reachable from a phone's own loopback. A mobile connection to that backend requires a separately provided credential-free HTTPS private endpoint and explicit private-route evidence. This code does not create that route or prove that endpoint maps to the desktop backend. The host must authenticate the selected deployment, verify protocol/capability compatibility and ownership, and observe transport access before supplying evidence. Arbitrary endpoints are untrusted; a network adapter must enforce endpoint/trust policy before requesting them. The helper never fetches URLs or probes credentials.

The declarative MCP UI contract accepts only bounded text, button, and form nodes from explicitly connected and trusted services. Host capabilities and user UI consent are required. The host owns service-scoped action policies and their required permissions; resource-provided permissions can add restrictions, never remove host requirements. `authorizeMcpAction` rechecks trust, connection, capabilities, and permissions before dispatch, supporting permission revocation. It does not dispatch actions. Render adapters must insert text as text and use isolated event handlers. Arbitrary HTML, JavaScript, frames, and unknown fields are rejected. This is a generic composition contract, not a completed MCP Apps transport adapter, sandbox renderer, native iOS/Android runtime, or application/store package.

Verification is offline synthetic: pairing/QR/manual selection, callbacks, consent, permission denial/retry, expiry, cancellation, abort, replay, backend checks/private routes, service trust/capabilities, and action policy/revocation. A strict TypeScript consumer checks the exported contract shapes. No Bend bridge is implemented by this slice.

## Durable host integration

The authenticated local HTTP boundary and transactional filesystem adapter are now available through `near-function/setup/host`. See [PROTOCOL.md](./PROTOCOL.md) for exact routes, response envelopes, lifecycle, storage limits and remaining production gaps. The original synchronous reference authority remains supported.
